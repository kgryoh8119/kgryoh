実施日：2026-10-13。改修前の版は残してあり、改修版は別名（`スムシティ_v2.html`、公開ページ「スムシティ v2」）です。

## 優先順位 1：保存と操作の信頼性

### 再現した不具合と修正

| 不具合 | 修正 |
|---|---|
| 同じ区画を 2 回含む道路操作で 2 区間分を請求 | 全てのタイル操作（建設・撤去・補修・用途）で重複を除く。プレビューと実行は同じ計画関数（`planRoad` など）を使い、区画数と金額が必ず一致する |
| 保存データの road に 9（国道を 9 にした状態も）が通る | `validateState()` で全配列の長さ・整数性・値域を検査。国道の行は必ず 3、市道は開発できる土地だけ |
| `borrow.amount = NaN`、`road = 9`、未知の建物種別を操作関数が受け付ける／例外 | `validateAction()` で型・整数・有限数・値域・実在する ID を実行前に検査 |

### 操作（`src/sim/actions.ts`、`src/sim/validate.ts`）

- 全ての操作は `dispatch()` を通り、①形式の検査 → ②実行 → ③状態全体の検査 → ④再計算と有限値の確認、の順に進む。
- 実行前に状態の写しを取り、②〜④のどこで失敗しても **資金・地図・工事・台帳・乱数を含め全てを元に戻す**。
- 失敗の理由は「操作名：理由」で返す（例：「市債の発行：市債の金額は正の整数（万円）で指定してください」）。
- 一時借入の残高が上限（2 億円）を超えると **財政危機** となり、新しい建設・道路・政策の開始は理由つきで止まる（既存施設の更新は可能）。

### 保存データ（`src/sim/save.ts`、`src/sim/validate.ts`）

- 検査する範囲：地図 5 配列の長さ・整数性・値域、国道の配置、建物の種別・座標・大きさ・状態と残り工期の対応・老朽度・戸数と世帯数・職員数、建物 ↔ 区画の **双方向** の対応、借入（種類・元本と残高・利率・期間・市債上限）、台帳と今月の記録、履歴、政策、効果、予定された効果の中身、イベント（実在する ID・重複）、公約、選挙記録、案内、乱数状態、月と任期。
- 再計算の前に不正値を弾き、再計算後も全ての集計値が有限であることを確かめる。
- 読込に失敗しても、いまの街はそのまま。
- 800 万文字を超える入力は解析せずに拒否する。深い入れ子は JSON の解析時点で拒否し、検証は固定の構造だけをたどるので、再帰で固まらない。
- 既存の v1 セーブ（月初の資金の記録がない形、全園共通の定員拡大）はそのまま読める。

### 財政（`src/sim/step.ts`）

- 台帳の各月に「月初の資金」を持たせ、**月初 ＋ 毎月の収支 − 返済 ＋ 借入 − 建設・更新・撤去 − イベント等 ＝ 月末** を毎月検算できる（`ledgerGap()`）。画面の［財政］に「先月の現金の動き」として表示。
- イベントの支出は事前に全額払えるかを確かめ、不足を黙って減額していた処理をやめた。
- 一時借入の残高は［概要］の課題と［財政］に表示。選挙では残高に応じて最大 −10 ポイント。

## 優先順位 2：予測

- 予測は **Web Worker（別スレッド）** で計算し、画面の操作と描画を止めない。単一 HTML のまま、ワーカーはページ内に埋め込み（blob URL）。起動できない環境では画面側で少しずつ計算する方式に自動で切り替える。
- 計算開始時の状態番号（`Game.rev`）を記録。**計算中に街が変わったら計算を中止**し、終わった結果でも番号が違えば「○年目○月時点の試算です」と古い結果として表示する。
- 進捗バーと「中止する」ボタン。計画案の破棄・採用でも計算は止まる。試算のあいだは時間を止める。
- 基準年月、計算時間、方式（別スレッド／画面側）を表示。12・60 か月の比較表に満足度・最大混雑率・借入残高を追加。
- 計画案では「効果が出る時期」を表示：操作ごとの説明（工期、採用、効果が満額になるまでの月数）と、待機・混雑・人口・資金・満足度について **何か月後から差が出るか**、12・60 か月後の差。

## 優先順位 3（一部）

- イベントを選んだ時点の待機・最大混雑率・資金・毎月の収支・地区別満足度を記録し、［声］の「これまでのできごと」で「選んだ時 → いま」を比較できる。
- 私立保育園の定員拡大は、イベントの対象となった園だけに効く（旧セーブの全園共通の効果も引き続き読める）。
- 保育園の着工時に「完成は 8 か月後、完成後に保育士を採用しながら受け入れが増え、工事中は定員に数えない」と表示。

## テスト（`npm test`、110 件すべて合格）

- `tests/robust.test.ts`（82 件）：

  - 不正な操作：道路種別 9・NaN・3、区画 −1・小数・地図外・文字列・空・多すぎ、用途 7・小数、未知の施設、座標 NaN・Infinity・小数・地図外、市債 NaN・Infinity・負・小数・上限超・文字列、未知の建物 ID、職員 NaN・負・小数・範囲外、未知の政策、未発生のイベント、範囲外の選択肢、未知の操作、null。いずれも拒否され、状態が 1 バイトも変わらない。
  - 資金不足の操作で状態が変わらない。設定値の誤り（建設費 NaN）を模して、実行途中の失敗が完全に元へ戻る。
  - 不正な操作を浴びせながら 24 か月進めても、有限のまま保存・読込できる。
  - 不正な保存データ 34 通り（国道を 9、水面の道路、区画と建物の不一致、ID 重複、工期と状態の矛盾、世帯数超過、借入の矛盾、未知の政策・効果・イベント、1e309、巨大入力、深い入れ子など）を拒否。読込失敗でもいまの街は不変。v1 セーブは読める。
  - 240 か月の財政：毎月の検算、月をまたいだ残高のつながり、市債上限、返済の完了。建設費・更新費・イベント支出・市債が台帳に 1 回ずつ。
  - 財政危機で建設・道路・政策が止まり、状態が変わらない。
  - 私立園 2 園のうち対象の園だけが拡張。イベント選択時の値の記録。工事中の保育園は定員に数えない。
  - 72 か月の通しプレイ：48 か月目に選挙、その後も毎月、状態の検証と台帳の検算が通る。

## 実測（この検証環境の値）

環境：クラウドの Linux コンテナ（CPU 2 コア、GPU なし）、Chromium 141 ヘッドレス、SwiftShader（ソフトウェア描画）、1440×900、devicePixelRatio 1。
**fps はソフトウェア描画のため全画質で 2〜3 fps で、実機の目安になりません。GPU のある端末では計測していません。**

| 画質 | 描画回数 | 三角形（影の描画を含む） | 影 | 車・歩行者（演出） | 建物 |
|---|---|---|---|---|---|
| 高 | 126 | 約 71 万 | あり（2048） | 118・155 | 315 |
| 中 | 126 | 約 70 万 | あり（1024） | 77・101 | 315 |
| 低 | 76 | 約 35 万 | なし | 41・54 | 315 |

| 計算 | 値 |
|---|---|
| 月次計算（ブラウザ内、1 か月あたり） | 2〜9 ms（計測ごとのばらつきが大きい） |
| 予測 60 か月 × 3 本（別スレッド） | 1.2〜2.0 秒 |
| 起動時の街の 3D 生成 | 約 0.35〜0.5 秒 |
| 操作 1 回の検証と写し | 数 ms（状態の写し 1 回分） |

改修指示書にある「予測 6.9 秒」は外部の計測で、同じ条件では再現していません。

## 既知の制限・未対応

- 優先順位 3 の「最初の 5 分の導線の作り直し」「道路接続・用途指定・公共と民間の違いを地図上で説明」は未着手。
- 優先順位 4 の見た目の改善（距離別の見え方、ラベルの重なり、文字のコントラスト）は未着手。GPU のある実機での fps も未計測。
- 公開ページ（Artifact）の枠内でワーカーが起動できるかは未確認。起動できない場合は画面側の計算に自動で切り替わる。
- スマートフォン実機のタッチ操作は未確認。
