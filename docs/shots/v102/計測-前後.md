# v102 前後の計測と描いた数（変更記録の抜き書き）

### 重さ（`scripts/v102-perf.mjs`、N=4 コマの平均。生の値は `docs/v102-perf-before.json`・`docs/v102-perf-after.json`）
三角形は影の描画の分を含む（カッコの中が影の分）。「描き終わり」は 1 画素を読み出して GPU（ソフトウェア描画）の終わりまで待った時間で、実機の数十倍遅い。比で見ること。

- 三角形は、中・高のどの場面でも減った（全景 −41〜−42%、地上 −29〜−31%、近景 −15〜−20%、駅前 −8〜−12%）。影の分は全景で −78%、地上で −35〜−41%。
- 後の方が描く住民の数ははるかに多い（下の表）。それでも三角形は減った。
- 低・全景だけ増えた（+24%）。内訳（`v102-diag.mjs`）では 1 台 約 4,800 三角形の精細な車が全景でも全部精細で描かれていた。その後に精細に描く距離の上限を入れた（表には反映していない。再計測していない）。
- draw call は全景で増えた（林の塊・影だけの形が増えたため）。近景・地上では減った。
- JS の時間はほぼ同じ（車・人の更新 3〜7ms。遠くを動く住民の分で 1〜2ms 増えた）。ソフトウェア描画では JS の ms の振れが大きい。
- 「描き終わり」は振れが大きく（同じ条件で ±20%）、はっきり言えるのは地上視点・中の全景が軽くなったことくらい。
- 雲は 6.9 万三角形しかなく、分けても効果はほぼなかった。いつも描いている MeshBasic の 44.6 万三角形の正体は確かめていない（区域の暗幕の重ね描きらしい）。次の候補。
