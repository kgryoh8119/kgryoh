# v103 変更記録

v102 の続き。4 つのことをした。

1. 駅前の幹線（朝 8 時）で、遠くの簡略な人が歩道でなく車道にいる不具合
2. 見る向きに関係なくいつも描いている約 44.6 万三角形の正体と、その削減
3. 「低・全景」の測り直し
4. 横断歩道を引く交差点の見直し（v101 で約束した分）

## 1. 車道にいる人

### 本当の原因（3 つ）

v102 は「曲がり角の向きの扱い」を疑っていた。調べると、それも一部だが、主な原因は別だった。

1. **着いた人が車道の真ん中に立っていた（いちばん大きい）。** 精細な歩く人（住民の移動）は、行き先の道路の区画に着いて建物へ入るとき、「いまの区画」と「次の区画」が同じになることがあった（途中から出した人が、はじめから行き先の区画にいる場合）。向きが無いので横へずらせず、区画の中心＝車道の真ん中に立ったまま、建物へ入る数秒を過ごしていた。朝 8 時は駅前の道路の区画が駅へ行く人の行き先なので、そこに人がたまる。注視点から遠い人は簡略な形で描くので、「遠くの簡略な人が車道にいる」と見えていた。駅前で測ると、精細な歩く人の位置の 3 割が車道の中だった。
2. **区画の中心どうしを結ぶ線を、いまの区画の幅だけずらしていた。** 簡略な人・車（v102 の `lodcrowd.ts`）も精細な歩く人も同じ。
   - 生活道路から幹線の交差点へ入ると、区画の後ろ半分を生活道路の歩道の位置（中心から約 3.7m）で歩き、幹線の車道の中を歩いていた。
   - 交差点の区画から二車線の腕へ出ると、交差点の区画の等級の幅を使い、二車線の車道の中を歩いていた。逆に生活道路へ出るときは、幹線の歩道の位置のまま家の敷地を歩いていた。
   - 曲がるときは区画の中心で向きが変わり、横へ飛んでいた（v102 が疑った所）。
   - 車も同じで、交差点の区画の車線（幹線なら中心から 5.6m）を、入ってくる生活道路の側にも使っていた。v101 で円弧にした曲がり角の道も、直線で横切っていた。
3. **駅のまわりの歩道に並ぶ人の位置が、生活道路では車道の中だった。** v102 の「駅へ歩く人」の立ち位置が、生活道路で中心から 2.1m（外側線の内側）になっていた。v101 で路側帯を外側線の外（2.5〜5m）に描くようにしたのに、合わせていなかった。

### 直したこと

- `src/render/farpath.ts`（新しい、純粋な関数）：車線と歩道の上の位置を、区画ごとに描いた道の形に合わせて出す。
  - 腕ごとの車道の半幅（roadbase の aE・aW・aS・aN と同じ決め方）。歩道の幅の中ほど（`walkW` の 3.5・3.0・2.5m の半分）を歩く。
  - 幅の変わる直線の区画は、縁石と同じく区画の中ですりつける。
  - 交差点で曲がるときは、入ってきた腕の歩道の線と出ていく腕の歩道の線が交わる角で曲がる。内側の角は道を渡らず、外側の角は横断歩道の位置で 2 本の道を渡る。まっすぐ交差点を抜けるときも、横の道の歩道の延長（横断歩道の位置）で渡る。
  - 円弧の曲がり角の区画は、円弧の歩道・円弧の車線に沿う。
  - 車は左側通行のまま。車線の位置は腕ごと（交差点の中でも、入ってきた腕・出ていく腕の車線）。
- 簡略な人・車と精細な歩く人は、次の次の区画まで決めて動く（曲がる前から曲がり方が分かる）。選び方は前と同じ（行き先へ向かう、朝の通勤は駅の方へ）。
- 動かない人（いまの区画＝次の区画）は、つながる腕の歩道の上に置く。
- 来た道へ戻る歩く人は、同じ側の歩道のまま向きを変える（前は道の反対側へ飛んでいた）。
- 精細な車の `lanePath` も同じ関数を使う。
- 駅のまわりの歩道の人は、歩道（路側帯）の幅の中ほどに置く。交差点では横の道を渡る所に立たせない。

### 確かめたこと

- `tests/v103_far.test.ts`：小さな街（幹線・二車線・生活道路、十字・T 字・曲がり角・行き止まり・途中で等級の変わる通り）で遠くの住民 1,600 人を 600 コマ動かし、人の位置 64 万・車の位置 32 万を全部調べる。人は車道に入らない（交差点で横断歩道の位置を渡るときだけ）、直線の区画では歩道の帯の外へ出ない、車は車道の中で直線の区画では左の車線。前の版の動かし方で同じことをすると、人の 1.3%・車の 3.7% が外れていた。境い目で位置が飛ばないことも確かめる。
- `scripts/v103-farcheck.mjs`：実際の街（住野市の駅前、朝 8 時）で同じ照らし合わせをした。結果は `docs/shots/v103/計測-前後.md` の下の表。遠くの人 1.1% → 0、遠くの車 5.5% → 0、精細な歩く人 29.8% → 0、精細な車 1.0% → 0。
- 画像：`goal-8am-before/after`（駅前の、駅へ歩く人の行き先の区画を斜め上から。前は車道の中に人が散らばり、後は両側の路側帯に並ぶ）、`far-station`・`far-main`（住民を全部簡略な形にして近くから）。

## 2. いつも描いている 44.6 万三角形

`scripts/v103-diag.mjs`（視錐台カリングをしない物を、view の持ち物の名前つきで並べる）で確かめた。**v102 の推測どおり、区域の暗幕（まだ編入していない区域を暗くする `lockMesh`）だった。** 住野市では編入前の 24,796 区画を、区画ごとに 3×3 の四角（18 三角形）で地形に沿わせ、地図全体で 1 つの形にしていたので、画面の外の分も毎コマ全部描いていた。

直したこと（`src/render/veil.ts`、純粋な関数）：
- 区画ごとに、地形に沿う細かさを 1 枚・2×2・3×3 から選ぶ。前の 3×3 の格子点での高さの差が 15cm 以内になる一番粗いもの（暗幕は地面から 1.2m 上なので、地面に潜らない）。急な山は前と同じ 3×3。
- 平らで同じ高さの区画は、横に続けて 1 枚にまとめる。
- 32×32 区画の塊に分けて、画面の外の塊は描かない。
- 区画の辺の上では地形（双一次の補間）は直線なので、細かさの違う区画が隣り合ってもすき間はできない。
- 色・透明度・重なり順は前と同じ。

結果：44.6 万 → 5.4 万三角形（−88%）。そのうえ画面の外の塊は描かない（中・近景では 0、全景でも見えている 5 塊・7,360 三角形だけ）。
見た目：同じ街の同じコマで、前の作り方の暗幕と新しい暗幕を描き比べた（`veilsame-*-old/new`）。違う画素は木や建物の上に散らばる、コマごとのゆらぎだけ。暗幕のある区域には差が無かった。
テスト：`tests/v103_veil.test.ts`（同じ所をすき間も重なりもなく覆う、高さの差 15cm 以内、三角形が大きく減る、塊をまたがない）。

## 3. 「低・全景」の測り直し

v102 の表の 664 万（v101 より +24%）は、全景で精細な車・人を描く距離の上限を入れる前の値だった。上限を入れた後の版（v102 の最後）で測ると 218 万で、v101 の 537 万より −59%。v103 では 174 万（−68%）。もう v101 より悪くないので、直すことは無かった。
全部の品質・場面の表は `docs/shots/v103/計測-前後.md`。どの場面も 42〜88 万三角形減った（ほぼ暗幕の分）。
JS と「描き終わり」の ms は、後の計測が画像の撮影と重なって CPU を取り合ったため、比べられない（表に載せていない）。

## 4. 横断歩道を引く交差点

v101 までは、二車線以上の道が通る交差点はすべての腕に、生活道路どうしの交差点でも 35% に横断歩道を引いていた。日本の住宅地の、生活道路どうしの一時停止の交差点には、横断歩道が無いことが多い。

新しい決まり（`crosswalkArms`、roadbase.ts の純粋な関数。腕ごとのビットを返す）：
- 信号のある交差点：すべての腕
- 学校・保育所・駅のまわり 3 区画の交差点：生活道路どうしでもすべての腕
- 二車線以上の道が通る交差点（幹線と脇の道を含む）：すべての腕（幹線を渡る横断歩道と、幹線の歩道を歩く人が脇の道の入口を渡る横断歩道）
- 生活道路どうし：引かない。止まれの標識・停止線・路面の「止まれ」・優先の側の点線は今までどおり
- 横断歩道の配置（`crosswalkLayout`）は v101 のまま

描画の側：横断歩道の縞・停止線・切り下げと点字ブロック・横断歩道の標識・歩行者用の信号・手前の区画のダイヤマークを、同じ答えから腕ごとに描く。ダイヤマークは、その先の交差点のこちら側の腕に横断歩道があるときだけにした。

歩く人の渡り方：`src/render/residents.ts` は住民の移動（経路・手段・人数）を決めるだけで、横断歩道を見ていない。渡る所は描画の側（1 の歩道の位置）で決まり、横断歩道があれば横断歩道の位置を渡る。生活道路どうしの交差点では、路側帯から交差点をそのまま渡る（横断歩道の無い交差点の、ふつうの渡り方）。信号のある交差点で赤なら手前で待つのは今までどおり。

テスト：`tests/v103_xw.test.ts`。画像：`xw-grid-before/after`（空き地に作った密な格子。前は生活道路どうしの交差点のいくつかに横断歩道があり、後は二車線の通る交差点だけに残る）。
