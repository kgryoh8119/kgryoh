# スムシティ v84　第 1 段階（ルールの整合性と操作の信頼性）変更記録

- 対象：v83 のビルド元（TypeScript / Vite）。単一 HTML はここから再ビルドしたもの（圧縮後のコードには手を入れていない）。
- 依頼文にあった `スムシティ１１.html` は受け取っていないため、その生成元にあたる v83 のソースを直した。依頼文の関数名（`hs`・`pTerm`・`$o`・`Zo` など）は圧縮後の名前なので、ソース上の対応する関数で確認した。
- 元の HTML（v83）は残し、改善版は別名 `スムシティ-v84-第1段階.html` で出力。

## 1. 既存機能の一覧（今回さわった範囲）

| 機能 | 場所 | 今回の扱い |
|---|---|---|
| 選挙の見込み・内訳 | `sim/step.ts` `electionOutlook` | 拡張（返り咲きも同じ関数で計算） |

## 2. 変更一覧

### A. 説明と判定の共通化

| 問題（v83） | 変更 | プレイヤーへの効果 |
|---|---|---|
| 返り咲き：判定は「満足が基準 −0.05 以上」なのに、画面の説明は別の数字（−0.02 相当）を書いていた | 条件の定義を `RERUN` と `rerunRules()` の 1 か所にし、画面の条件表・ボタンの有効／無効・理由文・CPU の判断をすべてそこから作る。判定そのもの（−0.05、支持率 50%、12 か月、一時借入なし）は現行のまま | 「条件を満たしたのに押せない」がなくなる。4 条件それぞれの「必要／いま／満たす・まだ」が表で見える |
| 当選：判定は 50 以上、説明は「50% を超える」。49.96% が「50.0%」と表示されて落選に見えることがあった | `WIN_VOTE = 50` を説明・判定・確率で共用。説明は「50% 以上で当選」。`voteText()` は丸めで線をまたがない（49.96 →「49.9」） | 表示された得票率と当落が食い違わない |
| 水道の公約：判定は 40 以下、説明は別の表現 | 説明を「老朽度 40 以下」に統一 | 目標値が分かる |
| 財政の公約：説明があいまい。記録が 0 か月でも達成扱いになりえた | 「直近 12 か月の収支の平均が 0 以上・一時借入なし」と明記。観測した月数を表示。記録 0 か月は「評価待ち」（達成にしない） | 何を見て判定されるか、いま何か月分で見ているかが分かる |
| 当選確率：表示は正規分布の近似、返り咲き画面はさらに別の式（+2 の補正を画面と本番で別々に足していた） | `winChance()` を、本番の抽選と同じ分布（3 つの一様乱数の和）から厳密に計算。返り咲きの補正は `electionOutlook(s, true)` に入れ、画面と本番が同じ関数を使う。風向きの幅 0 でも 0% / 100% を返す | 表示された確率どおりに当落が出る |

### B. 計画案は全件成功のときだけ確定

| 問題（v83） | 変更 | プレイヤーへの効果 |
|---|---|---|
| `commitDraft` が本番へ 1 件ずつ適用し、途中で失敗すると前半だけ残り、計画案も消えた | いまの本番の複製に全操作を適用し、全部通ったときだけ複製を本番にする。失敗時は本番も計画案もそのまま。何件目がなぜ通らないかを帯に表示し、「この操作を外す」で直せる | 中途半端に資金だけ減る事故がなくなる |
| 確定前に費用の全体が見えなかった | 試算モードの帯に、費用の合計・実行後の資金・毎月の維持費の増え方・完成までの最長月数を表示 | 押す前に負担が分かる |
| 確定が取り消しにつながっていなかった | 確定を取り消し 1 回ぶんとして登録（同じ月のあいだ） | 計画案を丸ごと 1 回で戻せる |

仮の検証は複製の上だけで行うので、通知（`onChange`・`onMonth`）や描画更新は確定したときに 1 回だけ出る。

### C. 保存の失敗を黙って無視しない

| 問題（v83） | 変更 | プレイヤーへの効果 |
|---|---|---|
| 年次自動保存の結果を捨てていた（失敗しても気づけない） | 保存の結果を `saveFail` / `lastOk` に記録し、失敗中は上の帯に赤い「⚠ 未保存」を出す。押すと保存画面が開き、「ファイルに保存する」「もう一度保存する」が並ぶ | 保存できていないことにすぐ気づき、その場でファイルへ逃がせる |
| 自動保存は先に「ひとつ前」へ回してから書くので、容量不足のとき新旧を失いかねなかった。中身だけ書けて要約が書けないと食い違ったまま残った | 先に新しい保存を書き、成功してから前のものを「ひとつ前」へ回す。失敗したら枠を書く前の中身へ戻す。壊れた自動保存で正常な「ひとつ前」を上書きしない | 最後に正常だった復帰点が残る |
| 失敗しても成功したように見えた | 成功時刻は成功したときだけ更新。保存画面に「最後に保存できたのは○年目○月」を表示。書いた内容を読み直して確認 | 「保存したつもり」がなくなる |
| 別の街を読み込む前の退避（自動保存）が失敗しても、そのまま読み込んでいた | 退避に失敗したら読み込みをやめる | いまの街を失わない |

## 4. 既存セーブの互換性

- 保存形式・版番号は変えていない。v83 までの保存データ・保存枠・自動保存はそのまま読める（移行作業は不要）。
- 新しく持つ情報（保存の結果、計画案の基準値）は画面側の一時的な値で、保存データには入れていない。
- 公約の判定は「財政：記録 0 か月は未達成」だけが変わる。記録が 1 か月でもある既存セーブには影響しない。
- 返り咲きの得票は式を 1 本にしただけで、補正の大きさ（+2・公約なし）は同じ。
