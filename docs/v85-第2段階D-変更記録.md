# スムシティ v85　第 2 段階 D「今月の街の課題を最大 3 件」変更記録

v84（第 1 段階）の上に、別の変更単位として加えた。保存形式は変えていない（v83・v84 のセーブはそのまま読める）。

## 変更

| 問題（v84 まで） | 変更 | プレイヤーへの効果 |
|---|---|---|
| 概要タブに「いま足りないもの」（上位 3 件）と「いまの課題と、できること」の 2 つの欄があり、同じ問題（保育・水道・混雑など）が別々の書き方で 2 回出ていた。課題の数にも上限がなかった | 2 つを 1 つの「今月の街の課題」（最大 3 件）にまとめた。元の過不足の一覧は「施設・サービスの過不足」として折りたたみで残した | まず何を見ればよいかが 3 件に絞られる |
| 並び順は「足りない割合」だけ | 重要度 = 影響する人 40 + 悪化の傾向 20 + 期限の近さ 20 + 戻しにくさ 20（`ISSUE_W`）。公約に入っていて未達成なら期限の点が上がる | 期限が近いもの・放置すると戻しにくいものが上に来る |
| 保育の待機には、原因にかかわらず「保育園を建てる」を勧めていた | 原因を 5 つに分ける：施設不足／職員不足／道路につながっていない／場所が合っていない（市内に空きはある）／完成待ち。職員不足・道路・完成待ちのときは新設を勧めない | 原因に合わない建設で資金を無駄にしない |
| 容量不足の施設が老朽化で止まっているときも新設を勧めていた | 止まっている施設があれば、まず更新を勧める | 同上 |
| 課題ごとに書き方がばらばら | 各課題を「何が／どこ（地図へ）／主因／対策の候補」の同じ形で表示 | 読み方が毎回同じ |

- 元データは既存のものを共用：声（`voices`）、満足を下げている要因（`satDrag`）、施設の稼働（`effCap`・`used`・`staff`・`connected`）、履歴（`history`）、台帳（`ledger`）。新しい計算系は足していない。
- 課題の計算は `src/sim/issues.ts`（`monthlyIssues`・`allIssues`・`careCause`）。読むだけで、状態・乱数を変えない。
- 対策のボタンは道具・地図・資料を開くだけ。建設や政策の変更は自動ではしない（唯一「止まっている施設をまとめて更新」は以前からある操作で、押したときだけ実行）。
- 課題の候補：保育、財政（一時借入・赤字・資金不足）、老朽化、ライフライン・学校の容量、道路の混雑、住宅不足、満足を下げている要因（上位 2 つまで）、再選の見込み、公約の期限。同じ問題は 1 件にまとめる（例：再選の課題があれば公約の期限は別に出さない）。

### 未検証

- スマホ幅での表示。
- 実在マップ（渋谷など）での課題の内容。計算は地図によらないが、画面では住野市だけを見た。
- 重みづけ（40/20/20/20）が実際のプレイで納得できる順になるか。はじめの街では「混雑 → 保育 → 住宅負担」の順。初回の案内（第 2 段階 E）で保育を先に扱うなら、順序の調整が要るかもしれない。
- 「初見のテスターが原因を説明できるか」（E の受け入れ条件）は人によるテストが必要で、未実施。
