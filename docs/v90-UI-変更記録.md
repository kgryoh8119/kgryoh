# スムシティ v90　UI「課題 → 施策 → 結果」を追いやすくする　変更記録

作者のレビュー指示「プレイヤーが直面する問題、選んだ施策、後の結果を追いやすくする」のうち、UI 担当分（課題からの導線、政策カード、住民の声からの移動、予測との差の年次報告、遊び方の入口）。
保存形式の版は変えていない（`decisions` は省略可能な項目。v85〜v89 のセーブはそのまま読め、記録は空で始まる）。

## 計算（`src/sim/report.ts`、DOM に依存しない）

| 項目 | 内容 |
|---|---|
| 指標 | `{ id, name, unit, better, tol, digits?, scope?, get(s) }` の配列。汎用 11 個：人口・転入−転出・保育の待機・学校の過密・最大混雑率・月の収支・市債残高・満足（全体／いちばん低い世帯類型／いちばん低い地区）・住宅費の負担。`registerIndicators(defs)` で外から足せる（同じ id は置きかえ） |
| 予測 | `projectBands(s, actions, 12)`：状態の複製に forecast モードの月次処理を 12 か月回す（基準 1 本）。幅は「基準の変化量 × 係数（3 か月 0.25・6 か月 0.35・12 か月 0.5）」と指標ごとの最小幅 `tol` の大きいほう。12 か月で約 0.35 秒（はじめの街）なので、3 本は回さない |
| 記録 | `s.decisions`（最大 40 件、古いものから捨てる）：月・見出し・分類・課題の鍵・実行前の指標・3/6/12 か月後の予測幅・主に見る指標・実績。`Game.act` が主要な操作（政策・建設・更新・増築・撤去・税率・用途・線引き・道路・線路・編入・市債など）の成功時に記録。用途・道路などを同じ月に続けて塗ったら 1 件にまとめる。予測は画面を止めないよう 60ms あとに計算。計画案の確定は 1 件。経営モードのときだけ |
| 実績 | `Game.tick` の月次処理のあと `updateDecisions`：3・6・12 か月たった記録に実績を入れる。予測の幅から外れた指標があれば、その間のできごと（events.log）・ほかの施策・景気の変化から要因を 1〜2 個 |
| 年次報告 | 年度末（4 月になったとき）と任期末（選挙の結果が出たとき）に `Game.reportDue` を立て、画面が `annualReport` で表示。施策ごとに 実行前 → 予測の幅 → 実績 → 差、と「良くなった／悪くなった／良い面と悪い面」 |
| 試算 | `trialOptions(s, issue)`：課題の対策のうち自動で試せるもの（建設は課題の近くの置ける空き地を自動で仮選び、止まった施設の更新、課題に効く政策）。`compareTrial` で「しない場合／する場合」の 12 か月後 |
| 街を変えない | 記録は `s.decisions` にだけ書き、街の計算は読まない。予測は複製で回し、本番の乱数を使わない（テストで確認） |

## 画面ごとの変更

### 概要タブ「今月の街の課題」（最大 3 件のまま）
- 各課題のカードの下に 4 つの段階ボタン：**① 原因を見る**（地図を課題の場所へ動かし色分けを重ね、重要度の内訳・いまの値・関係する住民の声を出す）／**② 対策を試算**（対策を選ぶと、しない場合とする場合の 12 か月後を同じ指標で並べる。太字が基準、小さい数字が幅）／**③ 実行**（試算したあとだけ押せる。もう一度押して確定。`game.act` に課題の鍵を付けて渡す）／**④ 数か月後の結果**（3/6/12 か月後の実績と予測との差。新しい結果があると「結果が出ました」）。
- 既存の対策ボタン（道具・地図・資料を開くだけ）はそのまま。②の試算は複製で計算するだけで、③を押すまで街は変わらない。場所や範囲を選ぶ対策（道路・用途・幅員）は「計画案で試してください」と案内。
- 開始直後（案内が終わったあと・最初の 2 年・課題からまだ実行していない）は、保育・老朽化・容量の課題（なければ 1 件目）に「まずこれ」を表示。既存のチュートリアルの間は出さない（二重にしない）。
- 課題が上位 3 件から外れても、課題から実行した対策の結果は「課題から実行した対策の結果」で見られる。
- 「📘 年次報告（今年度の施策と結果）」ボタン。

### 年次報告（新しいダイアログ）
- 年度末・任期末に自動で開く（その期間に記録した施策があるとき。オート中は出さない）。
- 「計算結果」（青いラベル・表）：期間の街の変化、施策ごとの 実行前／予測の幅／実績／予測との差（幅の外は色付き・要因つき）。
- 「住民の声」（茶色のラベル・引用の体裁）：いま届いている声の一部。数値と見た目で区別。

### 政策タブ
- 各カードを同じ並びに：費用（月額・初期なし）／効き始め（ramp）／対象（who と、いまの街の世帯数・人数）／期待効果（効く理由と「数値で試算する（12 か月）」で指標ごとの差と幅）／副作用（財政の負担と、説明文の負の面）／不確実性（低・中・高と理由）／権限主体（`authorityLabel` があればそれ、なければ owner/authority、政策は「市が直接」）。
- 長い文は折り返し（`overflow-wrap:anywhere`）。表は横スクロールの箱に入れる。

### 建設メニュー
- 建てる施設を選んだときの「おすすめの場所」の箱に、折りたたみ「費用・工期・権限など」（同じ並び）。おすすめのない施設でもこの箱だけ出る。建設メニューの一覧（権限担当が触る所）は変えていない。

### 声タブ
- 声の本文か「詳しく」を押すと、発言者の住む地区（声の地区、なければ場所の区画の地区）へカメラが移動し、色分けを重ねる。関係する指標（いまの水準）・発生の原因・市全体で満足を下げている要因・影響する施策（政策はボタンで政策タブの該当カードへ、施設は建設の道具へ）を表示。core.ts は変えず、声の鍵ごとの対応表を `src/ui/flow.ts` に置いた。

### 遊び方の入口
- 「保存・設定」の設定タブの先頭に「遊び方」：経営（いま）／自由建築（既存の sandbox モード。もう一度押して確定。経営に戻せないことを明記）／撮影（既存のフォトモード）／街歩き（地上視点）。タイトル画面の下に案内の 1 文。
- 自由建築では、既存の「直接配置」の道具（`sandboxPlace`、`checkPlace(…, free=true)`）で費用・土地の持ち主の制約なしに置ける。選挙・公約の画面は出ず、施策の記録も取らない。

## 操作の流れ（はじめての人）
概要タブ → 課題 1「まずこれ」→ ① 原因を見る（地図が動く）→ ② 対策を試算（例：保育園を建てる、待機 12 か月後 しない 72 人／する 29 人）→ ③ 実行（もう一度押して確定）→ 時間を進める → 3 か月後にお知らせ「結果が出ました」→ ④ で予測と実績の差 → 4 月に年次報告。

## loops.ts のつなぎ方
`src/sim/report.ts` の `registerIndicators` に、ループの指標を `{ id, name, unit, better, tol, scope, get: s => loopIndicators(s)[id] }` に変えて登録する（`tol` は指標の単位で「ほぼ同じ」とみなす差）。登録した指標は記録・試算・年次報告に自動で入る。
対策は `registerTrialOptions((s, issue) => loopOptions(s, id).map(o => ({ label: o.label, actions: [o.action], note: \`${o.authority}・${o.months} か月\`, cost: o.cost })))` で課題の②に加わる（課題の鍵とループの対応は統合時に決める。`issueIndicators` に鍵 → 指標の対応を足すと①④の表にも出る）。

### 気づいたこと（直したもの）
- 年次報告の「住民の声」に同じ文が地区違いで 2 回出た → 同じ文は 1 回に。
- はじめの月は収支の記録がなく 0 と出た → 今月の見込みを使う。
- 実行した課題が翌月に上位 3 件から外れると「結果が出ました」が見えなかった → 外れた課題の結果の欄にも 3 か月だけ表示。月が進んだら開いていた結果の欄は閉じる。

### 未検証
- 「結果が出ました」の表示そのもの（画面確認では、実行した課題が開いたままの結果の欄で見えていたため、印の数は 0。上の修正後の画面は撮っていない）。
- 任期末の報告（選挙の月）。年度末の報告だけ画面で確認。
- 実在マップでの課題の試算（建設の仮の場所選び）。住野市だけ。
- 予測の幅（係数）の妥当さ。基準 1 本＋係数のため、できごとや景気の影響は入らない（画面にそう書いた）。道路維持強化の試算で混雑率が +2 になるなど、小さな差は計算の揺れを含む。
- 自由建築・撮影・街歩きの入口ボタンを押した画面（tsc と既存の道具の流用のみ）。
- 人によるテスト（はじめての人が ①〜④ を迷わず進めるか）。
