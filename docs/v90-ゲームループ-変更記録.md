# スムシティ v90　3 つのゲームループ（選択 → 時間差 → 副作用 → 再判断）変更記録

作者のレビューの最優先項目「施設を増やす前に、3 つの『選択 → 時間差 → 副作用 → 再判断』のループを明確にする。各ループは、予測画面と結果画面で同じ指標を比較できるようにする」の、シミュレーション（`src/sim/`）側の仕組みと回帰テスト。UI（政策カード・課題からの導線・年次報告）は別の担当が、ここで公開した関数を呼んでつくる。

新しい施設は足していない。既にある因果（用途地域と民間の着工、駅の混雑、保育・学校の定員、老朽度と更新、迷惑施設、店の売上と閉店）を使い、欠けていた副作用・時間差・対策の選択肢だけを足した。

## 1. 公開した関数（`src/sim/loops.ts`、`src/sim/index.ts` から re-export）

| 名前 | 中身 |
|---|---|
| `LOOPS` | `{ id: 'station' \| 'aging' \| 'industry'; name; indicators: IndicatorId[] }[]` |
| `INDICATORS` | 指標の定義 `{ id, name, unit, better: 'up' \| 'down', scope: 'city' \| 'district' }[]`（25 個） |
| `loopIndicators(s)` | `Record<IndicatorId, number>`。いまの値。予測（`forecast` の各行の `loop`）・結果・期待効果のすべてでこの関数を使う |
| `loopOptions(s, id, { expect?, months? })` | `LoopOption[]`：`{ id, label, action, cost, monthly, months, target: { who, hh }, expect: { indicator, lo, hi }[], side, authority, ok, why? }`。`action` はそのまま `dispatch` に渡せる。`expect: false` で期待効果を省いて速く出せる（期待効果は 1 件あたり複製 2 本 × 12 か月で 0.3〜0.5 秒） |
| `expectOf(s, id, action, months)` | 対策 1 件の期待効果の幅だけを出す（ワーカーで後から計算する用） |
| `districtIndicators(s)` | 地区ごとの人口・満足・待機（産業と暮らしの「どの地区が得をして、どこが損をするか」） |
| `loopOfIssue(key)` | 課題の鍵から入口のループ |
| `rentBurden(s)`・`disasterLoss(s, k)`・`siteNear(s, kind, x, y)` | 指標の部品と、置ける場所の探索 |
| `renewCostOf(b)`（`loopHooks.ts`） | 先送りの割増しを含めた更新費（UI の更新ボタンの金額もこれに） |

- `ForecastRow` に `loop: Record<IndicatorId, number>` を足した（予測画面と結果画面で同じ指標を並べられる）。
- 課題（`Issue`）に `loop?: LoopId` を足し、入口になる課題の `options` の最後に `{ act: 'loop', arg: <ループ> }`（ラベル「対策の候補を比べる」、老朽は「維持・更新・先送りを比べる」）を足した。UI はこの `act` で `loopOptions` を開く。
- 期待効果の幅：対策を仮に実行した複製と、何もしない複製を、楽観（転入 1.2 倍）／慎重（0.8 倍）で `months` か月（既定 12）回し、差の小さいほうを `lo`、大きいほうを `hi` にする。できごとは起こさない（`forecast` と同じ回し方）。

## 2. 3 つのループ

（以下、表は §4 の観察と合わせて読む）

### 2.1 駅前再開発（station）

| | 中身 | 既存／追加 |
|---|---|---|
| 選択 | 駅（いちばん混む駅）から道路で 22 区画以内の空き区画を高層住宅に指定（`zone` 3）。民間がマンションを建てる | 既存（用途指定・民間の着工・駅に近いほどマンション） |
| 時間差 | 着工は毎月の確率（上限 4 棟/月）、完成まで 8 か月、入居はその後。翌月の転入はほぼ変わらない | 既存 |
| 副作用 | 転入・市税が増える／保育の待機、小学校の過密、駅の朝の混雑、道路の混雑が増える。供給が増える間は家賃が下がり、入居が進むと戻る | 既存の因果。指標を足した |
| 対策 | 開発負担金（追加の政策 `devLevy`：着工 1 戸 15 万円の収入。月の着工の上限 4 → 2 棟、着工のしやすさ −15%、家賃に約 6% 上乗せ）／小学校の増築（既存の `upgrade`。工事中は定員が下がる）／駅の近くに保育園（既存の `build`）／バスの増便と交通広場（追加 `busPlus`）／鉄道会社への増発の要請（既存の `pol railfreq`。v90 で電車の能力に効くように）／家賃補助（追加 `rentAid`）／容積の上限を下げる（`zone` 2） | 一部追加 |
| 指標 | 転入世帯（月）・住宅費の負担（家賃 ÷ 所得）・保育の待機・小学校の過密・駅の混雑率・道路の混雑率・市税・開発負担金（累計） | 追加（`loopIndicators`） |

見つけたこと：はじめの街（住野市）は浄水場が老朽度 78 で、水道の余力が 2% を切ると民間の住宅が建たない。容積を上げても、水道を足すか更新するまで何も起きない（老朽インフラのループが駅前のループを止める）。テストと観察では、先に小さな浄水場を足している。

### 2.3 産業と暮らし（industry）

| | 中身 | 既存／追加 |
|---|---|---|
| 選択 | ショッピングモール・工場の誘致（既存の `build`、来るかは企業しだい）／観光（既存の政策 `nightEcon`） | 既存 |
| 副作用 | 雇用・事業税・来訪者が増える／**大型店が近くの小さな店と買物客を取り合う**（追加：住民の買物の重み・来訪者の買物の分け方に大型店を入れた。近くの店ほど売上が下がり、赤字が続くと閉店）／近くの住民の買物は便利になる（追加）／大型店は買物客の車を集める（追加）／工場の空気・迷惑施設（既存） | 一部追加 |
| 対策 | 商店街の支援（追加 `shotengai`：小さな店の売上 1.12 倍、閉店の猶予 +3 か月）／立地の条件づけ・緩衝緑地（追加 `bufferZone`：迷惑施設の届く範囲 0.6 倍、景気 −0.5%）／搬入路と駐車場（追加 `logiRoute`）／地元雇用の協定（追加 `localHire`）／環境対策（追加 `kogaiTaisaku`：工場などの排出 0.7 倍） | 追加 |
| 指標 | 雇用・事業の税収・小さな店の売上・閉店（直近 12 か月）・幹線道路の交通量（混む上位 1 割の区間）・住宅費の負担・環境の満足・世帯類型別の満足（5 つ）・満足のいちばん低い地区（地区ごとは `districtIndicators`） | 追加 |

既存の挙動の変更：v89 までは、モールがあると「市外へ買物に出る人の重みが 0.75 倍」になり、市内の小さな店の売上がむしろ増えていた（モールが商店街の客を奪わない）。v90 では、この効果をやめ、大型店の重みとして住民の買物に入れた（市内の買物の割合 `shopLevel` には大型店の分も数える）。

## 4. 48 か月の観察（ふつう、住野市）

計測：`newGame()`（住野市・はじめ 5,661 人）、難易度ふつう、48 か月。できごとは最後の選択肢で処理、選挙の結果は捨てて続ける（`scripts/balance.ts` と同じ回し方）。自動プレイ以外の台本は `autoTurn` を使わず、台本の操作だけをする。駅前と産業の台本は、ループの差だけを見るため、はじめに小さな浄水場を足し、浄水場が老朽度 88 になったら市債で更新する（老朽の台本はこれをしない）。計測の台本は作業用（scratchpad）に置き、リポジトリには入れていない。列の名前は `IndicatorId`（§1）、満足・支持は 100 点満点、資金は一時借入を除いた額（万円）。

## 6. 未検証・見送ったもの

- **48 か月の観察は 1 つの街・1 本ずつ**（住野市・ふつう・種は固定）。ほかの地形・難易度・実在都市版、乱数の種を変えた複数本は回していない。v86 の 20 年の計測（8 地形）もやり直していない。モールの重みの変更（市外への買物の減りを大型店に置き換えた）は、v86 の 20 年の財政の数値を少し動かしうる。
- **老朽のループは、この街では「すぐ更新」が有利に出る**：はじめの浄水場が老朽度 78 と更新の時期を過ぎているため。長寿命化が効くのはもっと若い施設で、その条件の観察はしていない。統廃合（休止）は同じ種類の施設が 2 つ以上あって余力があるときだけ候補に出るため、はじめの街では出ない。
- **大型店の重み**（`BIG_STORES`）は仮定。48 か月の台本ではモールの影響は小さな店の売上 −6% で、閉店の続出は強い条件（テスト）でしか出なかった。高齢世帯の満足は台本ではむしろ上がった（近くの買物が便利になる分）。「車のない高齢世帯ほど損」を出すなら、高齢世帯の買物の便利さに大型店を入れない、などの調整が要る（未着手）。
- **工場の環境への影響は狭い**（既存の排出のぼかしと迷惑施設の範囲 2 区画）。`loopOptions` の工場の候補地は世帯の重心から近い順に探すので、街の端（住宅から離れた所）になることが多い。住宅のそばに置く選択は、プレイヤーが地図で選ぶ。
- **期待効果の幅は 2 本（楽観・慎重）× 既定 12 か月**：工期の長いもの（モール・工場は 24 か月）の効果は 12 か月の幅には出ない（`months` を 30 にすれば出るが、1 件 1 秒ほどかかる）。できごとは起こさない。UI はワーカーで計算するか、`expect: false` で一覧を先に出す想定。
- 費用が負の政策（先送り・料金改定）が、既存の政策の画面で「月 −120 万円」と表示されることは、画面では確かめていない（UI の担当）。
- 人によるプレイテスト・スマホでの表示は未実施。駅の混雑率は `core` の電車の能力（`railCrowd`）を使い、`big.ts` の駅の乗降の混雑率（画面の鉄道の資料）とは別の値（増発はどちらにも効くようにした）。
