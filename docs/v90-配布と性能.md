# v90 配布と性能

担当：配布の構成、読み込み時の表示、性能の計測、ライセンスと出典の点検。計測の元データは `docs/v90-perf-raw.json`、スクリプトは `scripts/v90-dist.mjs`（配布の確認）と `scripts/v90-perf.mjs`（性能）。

## 1. 配布の構成（確認した事実）

`npm run build` は 4 つの成果物を作る。用途は README の表のとおり。

| 成果物 | 大きさ | 用途 |
|---|---|---|
| `dist/index.html` ＋ `dist/maps/*.json` ＋ `maps/manifest.json` | 本体 6.7MB（gzip 2.1MB）＋地図 1.7〜2.9MB × 12 | 分割版（ウェブ公開用。要 http） |
| `dist/sumucity-standalone.html` | 30.8MB（gzip 13MB） | 単体版（オフライン・ファイル配布用。地図 12 件を埋め込み） |
| `dist/sumucity-artifact.html` | 14.6MB | 公開ページ（Artifact）用。地図 4 件 |
| `dist/sumucity-page.html` | 6.6MB | 公開ページ用の断片（地図なし） |

`scripts/v90-dist.mjs` の結果（Playwright のネットワーク記録と JSON.parse の呼び出しの記録）：

| 確認 | 結果 |
|---|---|
| 分割版：開始〜タイトル表示（1.5 秒待つ）で `maps/<id>.json` の要求 | **0 件**（地図の一覧 `maps/manifest.json` だけを読む） |
| 分割版：「保土ケ谷（まちづくり版）」を選んだあと | `maps/hodogaya.json` **だけ**（選ばなかった 11 件は要求されない） |
| 単体版：タイトル表示時に 20 万文字を超える JSON.parse | **0 回**（埋め込み 12 件は起動時に解析していない） |
| 単体版：「保土ケ谷」を選んだあと | 1 回（1.68MB。選んだ地図だけ） |

### 直したもの

1. **分割版で追加の 11 地図が遊べなかった**：タイトルは「ページに埋め込んであるか／取り込み済みか」だけで遊べるかを判断していたため、`dist/maps/` に地図があっても保土ケ谷以外は「データを取り込むと遊べます」と出ていた。ビルドが `maps/manifest.json`（約 0.7KB）を作り、タイトルが起動時にそれだけを読んで遊べる地図を判断するようにした（`scripts/make-page.mjs`・`src/maps/store.ts`・`src/ui/title.ts`）。地図そのものは選ぶまで読まない。なお開発サーバー（`npm run dev`）には manifest がないので、従来どおり追加の街は取り込みが要る。
2. **読み込みに失敗すると、その地図の種類を書き換えて「取り込みが要る地図」に変えてしまい、再試行もできなかった**：書き換えをやめ、原因つきの案内と「もう一度読み込む」ボタンを付けた。
3. **読み込み中の表示**：「地図を読み込んでいます… 1.2 / 1.7 MB」（サーバーが大きさを返すとき）。読み込み中は地図のボタンがすべて押せない（二重押しの防止）。
4. **失敗の原因の分類**（`lastMapFail`）：`file://` で開いた（単体版か `npm run dev` への案内）／オフライン／サーバーが返さない（HTTP 状態つき）／データが壊れている／通信の失敗。
5. タイトルに「この作品について（出典とライセンス）」を追加（§4）。

## 2. 性能の計測

**条件と限界**：Chromium（Playwright）・**ソフトウェア描画（SwiftShader）**・この環境の CPU・gzip つきの http 配信（brotli ならさらに小さい）。**実機の GPU、低性能 PC、実機のスマートフォンでの計測はできていない**。CPU の絞り（`Emulation.setCPUThrottlingRate`）、回線の絞り（Fast 3G 相当：1.6Mbps・遅延 150ms）、スマホ幅（390 × 844・`isMobile`）はあくまで目安で、実機の代わりにならない。

**計測の回数**：利用上限のため、**各条件 1 回**（指示の「3 回の中央値」ではない）。環境の負荷でぶれる（同じ条件でも、ほかの処理が走っていると数倍になった）。スクリプトは `RUNS=3` で中央値を出せる。

| 条件 | HTML 取得（応答完了） | タイトルが出るまで（開始から） | 地図を選んでから街が出るまで | JS ヒープ（タイトル → 街） |
|---|---|---|---|---|
| 分割版・架空の街（住野市） | 0.9 秒 | 1.7 秒 | 20.2 秒 | 12 → 56 MB |
| 分割版・保土ケ谷 まちづくり版 | 0.3 秒 | 0.9 秒 | 10.3 秒 | 12 → 151 MB |
| 単体版（http、30.8MB を gzip 13MB で配信）・保土ケ谷 まちづくり版 | 2.0 秒 | 2.4 秒 | 10.3 秒 | 11 → 111 MB |
| 分割版・Fast 3G 相当・保土ケ谷 まちづくり版 | 11.0 秒 | 11.4 秒 | 44.3 秒（地図 1.7MB の取得を含む） | 11 → 69 MB |
| 分割版・スマホ幅 390px・保土ケ谷 まちづくり版 | 0.1 秒 | 0.7 秒 | 5.2 秒（軽量表示・品質「中」で始まる） | 12 → 288 MB |

読み取れること：

- 起動の重さの大部分は **本体の転送と解析**（分割版の本体は gzip で 2.1MB）。Fast 3G 相当では、タイトルが出るまでに約 11 秒かかる。単体版は同じ回線では 13MB で約 70 秒かかる計算（実測ではない）。回線が遅い環境には分割版を勧める。
- 地図を選んでからの約 10 秒は、地図の取得・まちづくり版の生成・街の 3D 構築で、ソフトウェア描画ではそのうち描画の準備が占める。**実機 GPU での値は未計測**。
- 単体版の埋め込み 12 件（約 22MB の JSON）は、起動時には解析しない（§1）。単体版のタイトルまでが分割版より 1.4 秒ほど遅いのは、30.8MB の HTML の読み込みと解析のため。
- ヒープは街の大きさと品質で変わる。実寸の大きな地図の値は未計測。

**計測できなかったもの**：CPU 4 倍・6 倍の絞り（描画の重さで画面操作が通らず、時間切れになった。ソフトウェア描画では絞りの意味が薄いので打ち切り）、マップ切替（タイトルへ戻って別の地図）の時間、品質 low/mid/high ごとの三角形数と draw call（`view.stats` が、1 コマが数十秒かかるこの環境では更新されなかった。参考値は v88 時点の「高品質で 1 画面あたり約 1,400 万面（影を含む）」と、住野市で 513 draw call のとき 約 1,380 万面を読んだ 1 回だけで、品質別の差は取れていない）、アーティファクト版・実寸版の起動、v85 との比較。

### 自動で品質を下げる仕組み

`src/main.ts` の「5 秒ごとに fps が 24 未満なら下げる」（高 → 中 → 低）を、住野市で確認した。デスクトップの初回の既定は **高**で始まり、ソフトウェア描画（約 2 fps）では約 34 秒後に「中」に下がり、通知（「動きが重いため、描画の品質を「中」に下げました」）が出た（45 秒の観察では「低」までは行かなかった。さらに 5 秒おきに下がる設計）。つまり仕組みは働く。

### 品質の既定値についての提案（変更はしていない）

- 現状：画面幅 900px 以下またはタッチ端末は「中」＋軽量表示、それ以外は「高」。高は約 1,400 万面で、実機 GPU が弱いと下がるまで最大 5〜10 秒カクつく。
- 提案：(1) 初回の既定を「中」にし、フレームが安定して余裕があるとき（fps が 50 以上を 10 秒続けたとき）に「高」へ上げる提案を出す、または (2) 現状のまま、品質の下げを 5 秒でなく 3 秒の観察にする。理由：初見の人が最初に見る画面が重いと、遊ぶ前に離れてしまう。実機での fps の実測がないので、変更はせず提案にとどめる。

## 3. ライセンスと出典の点検

詳細は [ASSETS.md](ASSETS.md)（地図ごとの取得日・補った項目の表を含む）。要点：

- 地図（OpenStreetMap：ODbL、標高：国土地理院）：12 件とも `credits` は同じ。取得日は 2026-10-14（保土ケ谷）と 2026-11-11（ほか 11 件）。`format: 'sumucity-realmap'`、`version: 2`。補った項目は、範囲内に見つからなかった浄水場（配水池に置換）とごみ処理施設。同梱の地図は ODbL の派生データベースで、**再配布時の条件（出典の表示、同じ ODbL での提供）の具体的な手続きは未整備**。
- three.js（MIT）。配布物に MIT のライセンス文が残っているかは**未確認**。
- フォント（Zen Kaku Gothic New・Barlow Semi Condensed：SIL OFL 1.1）は **Google Fonts から読み込む**。単体版でも読みに行く（`dist/sumucity-standalone.html` に `fonts.googleapis.com` の `<link>` がある）。オフラインや失敗時は端末の日本語フォントで表示（文字は欠けない。字形が変わる）。同梱（OFL は許す）はサイズの面で未対応。
- 3D モデル（名所 48 点）：作者が Blender で制作（全 48 点の generator が Blender I/O。台本は `tools/blender_*.py`）。台本のないものがあるかは未確認。外部素材の使用は見つからなかった。
- 人物の動き：**Adobe Mixamo の動きから取り出した関節角度の数値**（`src/assets/anim.json`、約 25KB）が配布物に入っている。FBX 本体・キャラクターは入っていない。**Mixamo の利用条件との関係は未確認**（作者が確認する）。
- 音：Web Audio による合成（音源ファイルなし）。
- 画面での表示：タイトルの下部、新設の「この作品について（出典とライセンス）」、実在の街のゲーム画面の下部（`#credit`）。「保存・設定」の中には出典の欄がない（`src/ui/ui.ts` は別担当の範囲のため未対応）。
