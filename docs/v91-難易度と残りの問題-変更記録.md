# v91 難易度の調整と、受入検証で残った問題への対応

v90 の受入検証（`docs/v90-受入検証.md`）で、ふつうの難易度で住野市が得票 49.9%（施策を実行しながら 48 か月）、保土ケ谷が 19.5%（後半は施策なし）で 2 本とも落選した。作者の希望は「そんなに難しくしたくない」。あわせて「残った問題」の 5 項目に対応した。

## 1. 難易度

### 1-1. 原因の測り方

`scripts/balance.ts` と同じ回し方（できごとは最後の選択肢、公約は待機・人口・財政）を一時的なテストファイルにして、v86 の統合時点（`5b0379e`）・v90（`5fc167d`）・v91 で同じ条件で比べた。地形は海辺（住野市）・田園・都会・まちづくり版の保土ケ谷（`hodogaya-d`）。打ち手は 3 種類。

- **オート**：`autoTurn`（作戦「バランスよく」）。毎月たくさん手を打つ。
- **放置**：何もしない（できごとに答えるだけ）。
- **課題に素直に対応**：3 か月ごとに、今月の課題（上位 3 件）の上から、② 対策を試算に出る候補の先頭で、資金が足りて実行できるものを 1 つ実行する（「やめる」・注意（⚠）付き・「効果は小さい」の候補は選ばない。月の収支が政策の費用より小さいときは政策を始めない）。人の操作に近い「少しずつ手を打つ」打ち手として作った。乱数の種を変えて 3 本。

### 1-2. 調整前の結果（v86 と v90 の比較）

| 打ち手・期間 | 地形 | v86 | v90（調整前） |
|---|---|---|---|
| オート 12 年（選挙 3 回） | 海辺 | L43 W56 W59 | W52 W57 W61 |
| | 都会 | W62 W54 W56 | W62 W57 W51 |
| | 田園 | W65 W58 W60 | W55 W56 W60 |
| | 保土ケ谷（まちづくり版） | W65 W66 W65 | W69 W62 W61 |
| 放置 4 年（選挙 1 回） | 海辺 / 都会 / 田園 / 保土ケ谷 | 26 / 32 / 51 / 18 | 22 / 32 / 48 / 18 |
| 課題に素直に対応 4 年 ×3 本 | 海辺 / 都会 / 田園 / 保土ケ谷 | （v86 には課題の試算がない） | 平均 51.0 / 40.8 / 44.2 / 47.2、**4 勝 8 敗** |

分かったこと：

- **v86 から v90 で、同じ打ち手の得票はほとんど変わっていない。** オートは v86 で 11 勝 1 敗、v90 で 12 戦全勝。放置はどちらも大差で落選する。v87〜v90 の変更（治安の計算、相談窓口の政策、ゲームループの副作用＝家賃・学校・混雑・商店の売上、老朽の割増し、マップ拡大）を個別に戻す比較は、差がこの程度なのでしていない。
- v86 の「ふつうは公約を守ればほぼ勝てる（39 勝 1 敗）」は、**毎月たくさん手を打つオートの結果**だった。人の操作のように少しずつ手を打つと、v86 の時点でも得票は 50% 前後になる。受入検証の住野市（施策 5 件・資金 6 億円を使い残し）が 49.9% だったのはこれと合う。
- 課題から選ぶ人には、**課題の対策の候補の並び**も効いていた。v90 では候補の先頭に、混雑の課題での「容積を上げる」や、政策のやめる・始めるの切り替えが来ることがあり、素直に上から選ぶと街が悪くなった（下の 2-3 で直した）。
- 保土ケ谷の 19.5% は放置の結果。v86 でも放置すると 18% で、実在マップだけが極端に厳しいわけではない（課題に対応すれば架空の街と同じくらいの得票）。放置では支持率が下がる → 予算案が否決される → 満足が下がる、の悪循環に入る（支持 13〜16%・満足 35〜40%）。規模の係数（SCALE）と初期の課題の重さは、架空の街との差が小さかったので変えていない。

### 1-3. 調整（得票の式と難易度の係数）

| 難易度 | 得票の加算（`DIFFS.vote`） | 支持率の目標の上乗せ（`appr`） | 満足が基準より低いときの下げ幅（`satDown`、新設） |
|---|---|---|---|
| やさしい | +7 → **+12** | 0.05 → **0.07** | **0.5 倍** |
| ふつう | +2 → **+7** | 0.02 → **0.04** | **0.65 倍** |
| むずかしい | −1（そのまま） | 0（そのまま） | 1 倍（v90 と同じ） |

- `src/sim/config.ts` の `DIFFS`、`src/sim/step.ts` の `electionOutlook`（暮らしの満足の項：基準 `P.voteCenter` を下回った分に `satDown` を掛ける）。ふつうの説明文を「目の前の課題に素直に対応していれば再選できる」に変えた。
- v90 で入れた因果（多文化施策で属性による治安悪化をしない、ゲームループの副作用など）は戻していない。
- 支持率の上乗せは、支持率 → 予算案の可決 → 満足 の流れを通って、街の育ち方そのものも少し変える（放置の海辺で 4 年目の満足 47% → 59%）。

| | 都会 | 39.9 / 42.7 / 39.8（0 勝） | 52.8 / 49.1 / 51.7（2 勝） |
| | 田園 | 40.9 / 52.8 / 38.8（1 勝） | 50.3 / 44.5 / 38.9（1 勝） |

| | 計 | **4 勝 8 敗**（平均 45.8） | **8 勝 4 敗**（平均 50.8） |
| オート 8 年（選挙 2 回・ふつう） | 海辺 / 都会 / 田園 / 保土ケ谷 | （12 年で全勝） | W57 W63 / W66 W57 / W64 W67 / W73 W66（8 戦全勝） |

- 受入検証の住野市（暮らしの満足 66%・公約 2/3・支持率 48%・黒字）を新しい式に当てはめると、得票の見込みは 49.9% → 約 55%（難易度 +5、満足の項 −2.0 → −1.3、支持率の項 +0.4）。人の操作で「当選圏＝55% 前後」の目標に届く。
- オートは v86 と同じく全勝。課題に素直に対応する打ち手は 4 勝 8 敗 → 8 勝 4 敗（平均 +5 点）。
- 田園の落選 2 本は、上下水道が足りなくなって満足が 49〜56% まで下がった街（打ち手が水道の対策を後回しにした）。
- **気になる点**：ふつうでは、放置でも田園と保土ケ谷は当選圏（55・57%）になった。調整前は放置で支持率が下がり、予算案の否決が続いて満足が崩れていたが、支持率の上乗せでその悪循環に入らなくなったため。海辺・都会は放置で落選する。放置で勝てる街を残すかは作者の判断（支持率の上乗せ `appr` を 0.03 に戻すと放置の悪循環は戻りやすい）。

## 2. 残った問題

### 2-1. ループの入口が見つけにくい → 「街の 3 つの論点」

- 課題欄（上位 3 件はそのまま）の下に **「街の 3 つの論点」** を置いた：駅前（住宅・保育・学校・混雑）／老朽インフラ（維持・更新・先送り）／産業と暮らし（雇用・店・環境）。それぞれ、いまの指標の要約（例：水道などの余力 101%・老朽度 70 以上の施設 1 か所・5 年の更新費 19,620 万円）と **「対策を比べる」** のボタン。押すと課題と同じ ①〜④ の導線（原因・試算・実行・結果）がその場で開く。上位 3 件にその論点の課題があれば「上の課題にも」と印を付ける。
- 課題のカードにあった「対策の候補を比べる（費用・時間差・副作用）」「維持・更新・先送りを比べる」のボタンは、押しても何も開かなかった（`act: 'loop'` を受ける処理がなかった）。② 対策を試算を開くようにした。
- 実装：`src/sim/issues.ts` の `loopTopics`・`loopEntryIssue`（鍵 `loop:station` など）、`src/sim/loops.ts` の `loopOfIssue`、`src/ui/ui.ts` の `loopTopicsHtml`。
- 確認：`scripts/v91-check.mjs`（住野市・保土ケ谷とも 3 件出て、老朽インフラから更新・市債・長寿命化・先送り・料金改定・道路補修の候補が開く）。画像 `docs/shots/v90/pc-v91-topics.png`。

### 2-3. 対策の候補が長い・逆効果が混じる → 主な指標で並べ替え・上位 5 件

- 課題ごとの主な指標（保育→待機、混雑→道路の混雑率、住宅の負担→家賃の負担、老朽・水道→実効容量、店→店の売上 など。`mainIndicatorOf`）と、対策ごとの指標への向き（`OPTION_EFFECT`：+1 良くする・−1 悪くする。値は各対策の副作用の説明と v90 の試算の向きから）を `src/sim/loops.ts` に置いた。
- `rankTrial`（`src/sim/report.ts`）：主な指標を **悪化させる候補は外す**（混雑・保育・学校の課題での「容積を上げる」など）。課題に合わせた建設・更新を先に、ループの対策は効く順に。財源・先送りの選択肢（市債・先送り・料金改定・統廃合）は「この課題は良くならない（財源・先送りとして比べる選択肢）」、効果のほとんどないもの（混雑への道路維持強化など）は「この課題への効果は小さい」と印を付けて下に。同じ名前の候補は 1 つに。
- 画面（`src/ui/flow.ts`）は上位 5 件を表示し、残りは「ほかの候補を見る（n 件）」に畳む。
- 確認：住野市の開始時、混雑の課題は 8 件 → 5 件表示＋3 件畳む・容積を上げる案なし、保育の課題も同じ。画像 `pc-v91-trial-top5.png`。テスト `tests/v91.test.ts`。

### 2-2. 容積を上げる試算で水道の注意が出ない → 原因は 2 つ

1. **② を開いたまま月が進むと、候補と注意が開いた月のまま残っていた。** 月が進むと試算の結果は消していたが、候補（`ix.opts`）は作り直していなかった。受入検証では 8 か月に混雑の課題の ② を開き（道路維持強化の試算）、16 か月にそのまま「容積を上げる」を選んだので、水道に余力があった 8 か月の候補（注意なし）が使われた。月が進むたびに、開いている ② の候補を今月の状態で作り直す（`refreshIxOpts`）。
2. **注意の文（`p.note.bad.f90-warn`）が、「？」（説明の文の表示）を押さないと見えなかった。** パネルの `p.note` は既定で隠す決まり（v35）があり、注意にも効いていた。注意と実行できない理由（`p.note.bad`）は常に出す。
- 加えて、試算の 12 か月のうち、水道・下水・電力の余力がなく民間の住宅が着工できない月を数え（`projectBands` の `stall`）、用途を変える対策で 3 か月以上なら「試算の 12 か月のうち n か月は水道に余力がなく…」と出す（いまは余力があっても 1〜2 か月で切れる場合に気づける）。
- 確認：住野市で駅前の論点の ② を開いたまま 2 か月進めると、容積の候補に ⚠ が付き（0 か月は付かない）、試算で「着工できない 12 か月（水道）」と注意が画面の文字として見える。画像 `pc-v91-upzone-warn.png`。

### 2-4. 関係の薄い指標が並ぶ → 施策が効く指標に絞る

- 課題から実行していない施策（政策タブのスイッチなど）は、主に見る指標を「全指標のうち予測で大きく動く 3 つ」から選んでいたので、保育人材支援に更新費の見通しが付くことがあった。
- `actionIndicators`（`src/sim/report.ts`）：政策の効果の鍵（保育士→待機、`sat:`→満足、転入→転入超過・人口、道路→混雑率 など）、建設・増築・更新する施設の種類、用途・道路・税・市債、ループの対策の向き（`wire.ts` の `registerActionIndicators`）から候補を作り、その中で予測で大きく動く 3 つを選ぶ。関係が分からないときは人口・満足・月の収支（`GENERIC_FOCUS`）。
- 確認：テスト（保育人材支援の記録の指標は待機・収支などから選ばれ、更新費の見通し・想定損失を含まない）。

### 2-5. 実在マップのラベル

- 受入検証で見つからなかった理由：出典・取得日は「街のいま」の小さなラベルの title（押さないと出ない）と画面下の出典表記だけで、施設の詳細や概要の文は `p.note`（説明の文。「？」を押さないと隠れる）だった。「県警」は「都道府県警察」と書いていた。「区長」は保土ケ谷の役が横浜市長なので出ないのが正しい。
- 概要の「街のいま」に、説明の文とは別に常に見える欄を置いた：地域・実データ（地形・道路・鉄道・川・建物の位置）と出典・取得日・推計（世帯・人口・資産・施設の能力・財政など）はゲーム上の仮定・あなたの役（横浜市長。まちづくり版）・警察（神奈川県警察）と鉄道事業者が決め市は要望・協議すること。
- 施設の詳細：権限の主体と所有・運営の「都道府県警察」を地図の都道府県の名前で（神奈川県警察・東京は警視庁。`prefOf`・`localize`）。まちづくり版のゲームで置いた施設にも「推計（ゲーム上の仮定）」と出典・取得日を出す。
- 確認：保土ケ谷で「街のいま」に出典・取得日・推計・ゲーム上の仮定・役・警察が画面の文字として出る、交番の詳細に「市の権限：協議（神奈川県警察）」と「ゲーム上の仮定」。画像 `real-v91-label-home.png`・`real-v91-label-facility.png`。テスト `tests/v91_real.test.ts`。

## 4. 未検証

- 自動の打ち手は人の判断の代わりにすぎない（少ない本数・4 年）。人によるテスト、むずかしい・やさしいの全地形、8 地形 × 5 回の長い回しはしていない。
- 「課題に素直に対応」の打ち手は田園で 3 本中 2 本落選した（水道・下水の不足を後回しにした）。
- 放置でも当選圏になる街（田園・保土ケ谷）が出た（1-4 の気になる点）。
- 受入検証の台本（`scripts/v90-accept.mjs`）の 48 か月の通しは流し直していない（該当の場面だけ `v91-check.mjs` で確認）。スマホ幅の表示は見ていない。
