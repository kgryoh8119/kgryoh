# v93 未検証分の検証（v91・v92 で残った項目）

v91（難易度の調整と残りの問題）・v92（地図を 192×168 へ広げた）で「未検証」と書いた項目を、この環境（CPU 4 コア・GPU なし・ソフトウェア描画の Chromium）でできる範囲で確かめ、見つけた問題を直した。

**この環境で検証できないもの**：実機 GPU での描画の重さ・空き地の塊を遅れて作るときのひっかかり、実機のスマホ（タッチの操作感・実際の画面の細さ・発熱）、人によるテスト（人が課題を読んで選ぶときの勝ちやすさ）。下の「勝率」はすべて自動の打ち手によるもので、人の判断の代わりにすぎない。

## 1. 全地形・全難易度の長い計測（8 年・選挙 2 回）

### 手順
- `scripts/balance-v93.ts`（`scripts/balance.ts` の回し方に打ち手 3 通りと NaN・例外の検査を足した。esbuild で 1 本にまとめて node で実行。実行方法は先頭の注記）。できごとは最後の選択肢、公約は待機・人口・財政（balance.ts と同じ）。**落選しても任期を続けたことにして 2 回目の選挙まで測る**（2 回目の得票は「落選した市長がそのまま続けた場合」の参考値）。
- 打ち手：**オート**（`autoTurn`）／**課題に素直に対応**（3 か月ごとに今月の課題の上位 3 件の上から、② 対策を試算の候補の先頭で実行できるものを 1 つ。⚠ 付き・「効果は小さい」などの印付き・「やめる」は選ばない。政策は月の収支が費用より小さければ始めない。画面と同じく施策の記録を残す）／**放置**。
- 8 地形 × 3 難易度 × 3 打ち手 = 72 本（各 1 本）。ふつうの「課題に素直に対応」は乱数の種（地図）を変えて 3 本。CPU 4 コアで並列 2。計 190 本を回した（調整の前後を含む）。生データは `docs/v93-balance/`。
- 1 回目の選挙が「再選」（v91 の目標「ふつう：課題に素直に対応すれば再選できる」の対象）。2 回目は 3 期目で、「多選」の批判が入る。

### 見つけた問題と直したもの
1. **課題の候補を上から素直に選ぶと、毎月の費用のかかる対策が積み重なって財政が崩れる。** 鉄道会社への増発の要請（月 200 → 500 → 900 万円）、家賃補助、政策などを課題ごとに足していき、月の収支が赤字 → 2 期目に一時借入 → 満足と支持率が崩れる（盆地：L48 → L25、資金 54 万円・一時借入 3 億円）。画面では赤字になることがどこにも出ていなかった。
   - 直したもの：試算の候補に **「この対策の毎月 n 万円で、毎月の収支（直近の平均 m 万円）が赤字になります」** の注意（⚠）を出す（`src/sim/report.ts` の `deficitWarn`。ループの対策・課題の政策・課題で建てる施設の維持費）。毎月の費用が 150 万円までで、資金が赤字の 3 年分より多いときは出さない（はじめから赤字の山あいの村で、すべての候補に注意が付いて何も選べなくなったため。150 万円の線を入れる前は、鉄道の増発が資金を理由に素通りして、盆地で 2 期目に一時借入 4 億円になった）。
2. **容積を上げる・下げるを繰り返す。** 混雑の課題では「容積の上限を下げる」、住宅の課題では「容積を上げる」が候補の上に来るので、素直に選ぶと 3〜9 か月おきに上げ下げしていた（海辺：上げる → 3 か月後に下げる → 3 か月後に上げる…）。
   - 直したもの：12 か月以内に逆向きの容積の変更をしていれば、その候補に「n か月前に『…』を実行したばかりです。すぐ戻すと、効果が出る前に打ち消し合い…」の注意（`src/sim/wire.ts` の `undoWarn`。施策の記録 `decisions` から読む）。
- テスト：`tests/v93.test.ts`（注意が出る・出ない条件、容積の戻しの注意、赤字のときの試算の候補）。
- 難易度の係数（`DIFFS`・`electionOutlook`）と地形ごとの初期条件は**変えていない**（下の結果で、ふつうの課題対応が 1 回目の選挙で負け越す地形がなかったため）。

### 目標に照らして
- **ふつう・課題に素直に対応**：1 回目（再選）は 24 本中 22 勝（平均 56.3%）。負け越す地形はない。落選 2 本は田園（50.0%）と山あい（49%、はじめから赤字の小さな村の地図）。修正前は 1 本ずつで 7/8 勝だったが、2 期目に財政が崩れる街が多かった。

## 4. 広げた土地の上空からの見え方

### 原因
- 全景の細かい市松模様は、地面の色（v88 の extDeco の印）ではなく、**空き地に置く田畑・草地の飾り**が原因だった。`drawEmpty`（細かい版）と、遠くの塊の簡略版が、区画ごとの乱数で「田んぼ・畑・草地・木立」を選び、明るい緑と濃い緑の箱を 1 区画ずつ置いていた。地面の頂点ごとの乱数のむらと、畑のうねの縞（頂点の間隔 10m より細かい縞で、区画ごとのまだらに見えた）も重なっていた。

### 直したもの
1. **見た目の印を大きなまとまりに**（`src/sim/map.ts` の `extDeco`）：区画ごとの乱数で選ぶのをやめ、ゆがめた大きなむら（15〜20 区画）で田んぼの集まり・畑・草地・屋敷林・空き地を決める。区画ごとの乱数は境目を 3×2 区画の田畑に沿わせる小さな揺らぎだけ。割合は地形ごとの v88 の表のまま（海辺：田んぼ 46%・畑 22%・草地 25%・屋敷林 5%）。はじめの町のまわり（76×68 の内）にも広げた（広げた土地だけ変えると境目が四角く見えた）。見た目だけの印で、計算には使っていない。
2. **空き地の飾りを印に合わせる**（`src/render/scene.ts` の `extLook`・`drawEmpty`・簡略版）：田んぼは田んぼの面（v70 の季節で色が変わる面）だけ、畑は 3×2 区画の畑ごとに同じ作物、草地は木をまばらに、屋敷林は常緑樹を多めに。乱数の田畑の箱は置かない。無人島と実在マップは変えていない。
