## 1. 橋脚

**原因**：立体交差の高架の橋脚を「区画の境目ごと」に立てていた。交差点の区画の境目＝交差点の中心から 15m は、ちょうど横断歩道
（交差点の区画の端、中心から 半幅＋0.6〜4.6m）のすぐ先で、高架の真下の内側の車線の上だった（作者の画像の場面）。
また陸橋（跨線橋）の橋脚は区画の中心、つまり線路の真上に立っていた。

**直し方**
- `grade.ts` に `flyPiers(s, span)`：橋脚を立ててよい区画（道の向きの座標）。高架の区間（坂を含む）のうち、
  **交差点（3 方向以上）の区画と、脇道のつながる区画を除いた区画の中心**だけ。交差点は前後の区画の中心どうし（60m）の桁でまたぐ。
- 高架の下の地上は側道（外側の車線、中心から 5.6m）だけが通る（v94 の deckStep）。内側の車線の帯（中心から ±3.2m）は
  **中央分離帯**として、縁石・植栽・低木を描き、橋脚（1.4m×5.2m、桁の幅の柱頭つき）はその中にだけ立てる。
  分離帯も交差点・脇道の区画には描かない。坂の低い所（路面 0.8m 未満）は描かない、桁下 1.2m 未満では橋脚を省く。
- 陸橋：橋脚を区画の両端（線路から 12.5m）の、桁の両縁の下へ移した（線路の上に立てない）。

前後：`docs/shots/v95-incident/before-pier-cross.jpg`（横断歩道の先の車線に橋脚）→ `after-pier-cross.jpg`（分離帯の中、交差点の外）。
`before/after-pier-side.jpg` は坂の側。撮影は `scripts/v95-pier.mjs`（v94-junction の場面）。
陸橋はこの地図で場面を作れず（踏切が見つからない）、**撮っていない**。

## 2. 重ならない・傾斜に沿う

- **車の坂の傾き**：`View.slopePose()`。前後の車輪（中心から ±0.8×半長）の路面の高さ（`vehY`、高架の上も含む）から車体のピッチを出し、
  向き（yaw）に掛ける。高さは前後の平均。路線バス（moveBuses）も同じ。前は中心 1 点の高さで水平のまま、坂でめり込む・浮いていた。
- **交差点で突き抜けない**：毎こま、交差点（3 方向以上）の中（中心から 半幅＋4m）と停止線を越えた車を、入ってきた区画つきで集める。
  交差点に入る前の車は、別の向きから入った車がいれば停止線で待つ（先に入った車が優先）。向かい合う直進・左折どうしは待たない（右折は対向と交わるので待つ）。
  赤色灯の緊急車両・高架の上の車は待たない。8 秒待っても空かなければ進む（行き詰まり防止）。信号は従来どおり。
- **同じ車線の車間**は v83 からの仕組み（前の車の長さ＋車間）のまま。
- **歩行者の位置（作者の追加の指摘）**：原因は、立体交差の前後で 6 車線の幅に広げて描いた幹線（`wideSet`）の上で、歩く位置を
  幹線の半幅 5m のまま計算していたこと（歩道の中心 6.25m ＝ 外側の車線 5.6m の上）。連れ歩きの人（lead）は先頭と同じ区画・同じ側を
  歩くので、2 人そろって車道に出ていた。`pedHW()` で描いた幅（拡幅は 7.5m）に合わせ、幅の違う区画の境目ではなめらかに寄せる。
  信号の停止位置・建物への出入りの距離も同じ幅で計算する。車の信号の停止線も拡幅した道では横断歩道の手前になる。
- **歩行者どうし**：2m 四方の格子で近くの人だけを見て、前（1.6m 以内）や正面に人がいれば横へ 0.55m ずれて追い越す・すれ違う。歩道の幅の中にとどめる。
- 車線の位置（中心から 1.9 / 5.6 / 2.5 / 1.25m）と柱：橋脚は分離帯へ移したので側道の車と重ならない。信号柱・電柱は roadkit が歩道側に立てるもので、今回は変えていない。

検査：`scripts/v95-incident.mjs` の前半が、交差点以外の区画で描いた車道の半幅より内側にいる人を数える（before / after を同じ場面で）。

結果（同じ場面、20 秒ずつ 3 回）：直す前は 91 人中 3〜4 人が拡幅した幹線の車道の上（中心から 6.25m・6.87m、描いた半幅 7.5m の内側）。
うち 1 組は連れ歩き（lead）で、作者の画像と同じ「2 人連れが車線の上」を再現。直した後は 99〜101 人中 0 人。
画像：`before-peds-wide.jpg` / `after-peds-wide.jpg`。

## 3. 事故と緊急対応の連鎖

決まりは `src/render/incidents.ts`（種類の選び方・重さ・出動する車・文言・知らせのまとめ方）、動きは `scene.ts`（v87 の dispatch / emTick の上に足す）。

| できごと | 起き方 | 出動と連鎖 |
|---|---|---|
| 追突 | 見ている所の近くを走る車（交差点・高架・坂の外）が止まり、見ていない所の車をその真後ろに連れてきて 2 台とも止める | パトカー（交番・警察署）→ 着くと三角コーン 4 本と警察官（検証・誘導）。けが人（重さ 2 以上）で救急車 → 病院。重い（3）と交番から応援のパトカーと白バイ。最後にレッカー車（警察官がいる間は待つ）が来て、離れるときに事故車を片づける |
| 接触（4 車線） | 隣の車線どうしで斜めに止まる（狭い道では追突になる） | 同上 |
| 歩行者 | 車が止まり、前に人が倒れる（控えめな形） | 救急車 → 着いて離れるとき倒れた人を乗せて病院へ。重いときは 30% で病院で亡くなり、霊柩車（黒い車、赤色灯なし）が病院から葬儀場・斎場（無ければ市外の入口）へ |
| 車両火災 | 止まった車から煙と火の粉 | 消防車・救急車・パトカー。放水（既存）で火が弱まり、消えるまで消防車は帰らない。焼けた車は黒くなりレッカーなしで残り、時間で片づく |
| 建物火災 | 近くの家・店から屋根の高さで煙と火の粉 | 消防車・はしご車・消防車・救急車・パトカー。放水 |
| スピード違反・信号無視 | 走る車に 7 区画先までの道筋を決め、1.7 倍の速さで走らせる（信号無視は赤でも止まらない） | 白バイかパトカーが同じ道筋を赤色灯で後ろから追い、道筋の終わりで違反の車を左に寄せて止め、後ろに付いて 22 秒（切符）。終わると交番へ帰る |
| 駐車違反 | 近くの 2 方向の道に、路上に止めた車を置く（後ろの車は右へよけて抜ける） | パトカー（赤色灯なし）が来て、着くとフロントに黄色い標章。帰ったあとしばらくして車は走り去る |
| 鉄道の人身事故 | 見ている所に近い列車を 75 秒止める | パトカー・救急車。知らせは「列車の運転を見合わせ」。駅の人だかり（既存の満員の表現）を増やすのは**未実装** |

- 拠点：パトカーは最寄りの交番・警察署、応援と白バイは交番（無ければ警察署）、救急車・消防車は消防署、レッカーは警察署から。
  拠点が無いと市外の入口から（16 秒遅れ、知らせに「到着が遅れます」）。遠い（45 区画超）ときも遅れの扱い。
- 同時に起きるのは 2 件まで、緊急車両は 12 台まで（軽い画質は 7）。人口 300 人未満と、遠くから見ているとき（距離 1100 超）は起きない。
- 知らせ：画面の右下に小さく（`#incfeed`）。同じ種類・同じ地区はまとめて「×2」、3 件まで、14 秒で消える。押すとカメラがそこへ行く。
  地区の名前は地図の地区（`DISTRICTS`）。

### (b) 住民のシミュレーション との取り決め（口）

- `view.onIncident?: (e: IncidentEvent) => void`。`e = { kind: 'crash'|'pedestrian'|'fire'|'violation'|'train', tile, month, severity, sub?, fatal? }`。
  できごとが起きた時に 1 回。`severity` は 1 物損・2 けが人・3 重い（違反は 1）。
  **病院で亡くなったときは、同じ kind・tile で `fatal: true` をもう 1 回送る（件数には数えず、死者 1 名の追加として数える）。**
  `sub` は細かい種類（rear / cross / ped / carFire / bldFire / speed / signal / parking / rail）。
- `view.incidentRate?: (tile, hour, kind) => number`：その場所・時間帯の起きやすさの倍率（1 が標準）。無ければ 1。
  これに時間帯の目安 `hourRate(hour)`（夕方 1.5・朝 1.25・深夜 0.45）を掛け、`incInterval(rate, pop, r)`＝`150 秒 ×(0.55〜1.45) ÷ (rate × 人口の係数)` で次までの秒数を決める。
  人口の係数は 2 万人で 1（0.15〜1.6）。標準で見ていて数分に 1 回。
- 検査用：`view.startIncident(sub?)` で 1 件起こす、`view.incAuto = false` で自動を止める、`view.incInfo()` でいまのできごと。
- 統合は (b) の担当（main.ts でつなぐ）。この版では main.ts は触っていない。

## 未検証・残り

- 撮影は software 描画で遅く、事故の連鎖は `scripts/v95-incident.mjs` の場面（追突・歩行者・建物火災・スピード違反・駐車違反）だけ。
  車両火災・接触・鉄道の人身事故・霊柩車（重い事故の 30%）・応援の白バイは画面では確かめていない（コードの経路のみ）。
- 交差点の譲り合いで、渋滞時に交差点の手前の待ちが増える可能性（8 秒で抜ける）。長時間の遊びでの詰まりは見ていない。
- 歩行者は、横断歩道以外で車道を渡る動きはもともと無い（区画の歩道の上だけを歩き、交差点の区画で角を回る）。左右を見て渡る表現は作っていない。
- 歩行者と車・柱の重なりは、歩道と車道の位置で分けているだけで、個別の判定はしていない。駅の人だかりの間隔は既存のまま。
- 中央分離帯の植栽の色が、光の当たり方でピンクがかって見える所がある（舗装の色と近い）。
- 地形の起伏の坂での車の傾きは `surfY` の路面の高さに沿う（橋・高架・陸橋を含む）。自転車・二輪も同じ式。歩行者は体を垂直のまま足元の高さを合わせる（従来どおり）。
